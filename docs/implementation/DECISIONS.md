# Implementation decisions

- Preserve the approved Auraflare storefront/admin typography, photography, cream/wine colours, cards and introduction. Port components into one Next.js application; do not retain the separate legacy Vite/SQLite server.
- Laravel 13/PHP 8.5, MySQL 8.4 and Redis are authoritative. The generated TypeScript contract is shared through a pnpm workspace. TanStack Query and React Hook Form handle browser cache/forms consistently.
- The actual catalogue has no development products. Only the confirmed Kerala state allowance is seeded. Owner controls add active city/PIN exceptions. An explicit PIN deny wins; otherwise PIN, city and state rules are evaluated in that order. Confirm this precedence and delivery SLA before launch.
- An order request reserves ready stock and snapshots price/contact/address/tax. Shipping remains null until an owner issues a quote. Quantity, address and items cannot be rewritten after submission; eligible requests are cancelled and recreated.
- INR paise are integers. `TAX_POLICY` is unset until the business confirms `none` or `exclusive`, with a basis-point rate. These are configurable implementation choices, not a tax opinion or a business assertion.
- Lock sorted inventory balances, order, reservation and then financial records. Permanent unique stock-effect and payment-receipt keys prevent duplicate settlement. HTTP idempotency records do not imply exactly-once provider calls.
- Razorpay order/refund calls run after internal intent is committed. An ambiguous create stays unknown; reconciliation matches the internal receipt. Authorization never means paid. Delayed failure cannot regress capture. Late/excess captures remain financial exceptions; refund and physical stock return are separate actions.
- Direct orders use the same price/stock workflow and are not assigned to the staff member entering them. Guest order access is a separate order-scoped server grant; emailed recovery tokens are hashed/single-use. A verified matching customer explicitly claims an accessible guest order.
- Resource authorization for customer/guest order access uses OrderPolicy through Laravel Gate, with an explicit Actor context. Capability middleware guards global owner/fulfillment operations before input validation.
- Same-origin, host-only HttpOnly sessions with CSRF. No passwords, tokens, addresses or payment proofs in localStorage. A secure emailed token lives in a URL fragment until exchanged, then is removed. Existing invited accounts must sign in as the invited address; invitations never reset another account’s password.
- Public API/media routes currently share the session stack, so their responses use private/no-store caching. Server-rendered public pages fetch current catalogue/content; static first-party assets remain cacheable. This prevents a shared cache from distributing a session cookie.
- Proof attachments stay quarantined during scanner outages. Only an exact clean scanner response enables access; infected files are rejected. A screenshot never confirms funds. Private downloads recheck owner membership and expiry.
- Local storage and an S3-compatible private bucket are supported behind the media API. The emulator round trip verifies SDK compatibility only. Real cloud bucket IAM, lifecycle, encryption, delivery and ClamAV operation remain environment qualification steps.
- External mail defaults off; the durable outbox produces private local previews. Delivery retries are at least once: a crash after an SMTP send but before recording completion can duplicate a notification. Choose a mail provider with message idempotency before requiring stronger guarantees.
- Local prototype source is preserved by the backup tag. Legacy data is not a production migration source. New deployment needs Laravel, workers, storage and MySQL; GitHub Pages cannot execute it.
